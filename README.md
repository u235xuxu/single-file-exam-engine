# single-file-exam-engine

**把「一堆知识点」变成「能答的卷子」。生成一个 HTML 文件，双击就能考。**

A question bank goes in, a single self-contained HTML exam comes out. No server, no CDN, no dependencies.

> ### 👉 [先花 2 分钟做一遍，比看十段介绍管用](https://u235xuxu.github.io/single-file-exam-engine/examples/demo.html)
> 打开就是一份 10 题的卷子。答完立刻判分、给解析、标出错在哪。

---

## 你是不是也这样

花两个月整理了厚厚一叠复习资料，公式表、对比表、易错点，做得挺漂亮。

然后打开资料看了一眼，**觉得自己会了**。

考场上发现自己不会。

**因为「看过」和「答对」是两件事，中间差的是一遍一遍地做。**

要做题，就得有一份卷子。而做一份卷子，传统上有三条路，每条都堵：

- **买/找现成题库** —— 题目不是你的重点，别人的重点覆盖不了你的盲区
- **用在线题库网站** —— 要注册、要联网、要会员，题目你还不能改
- **自己写网页** —— 写十套题等于把前端写十遍

**这个项目把第二条路修通了：你只管写题，界面交给引擎。**

```
python3 build.py bank.yaml
→ bank.yaml.html    ← 全部产物。发给任何人，双击就考
```

---

## 具体省在哪

假设你要做一套 50 题的模拟卷。

| 做法 | 花多久 |
|---|---|
| 手写 HTML 页面 | 一整天，而且改一次题重排一次 |
| 用在线题库平台 | 注册 + 建题库 + 学习它的导入格式 + 会员费 |
| **本工具** | **写 50 道题的文本，一条命令** |

改题也一样：打开 `bank.yaml` 改一行，重新生成。**不用碰任何前端代码。**

产物是单个 HTML，所以：

- 教室没网也能考
- 微信直接发给同学，他双击就能做
- 放进 U 盘、放进任何静态托管，都不需要额外配置

---

## 为什么是单文件

不是技术炫技，是**分发的成本**。

任何需要「先装个什么」「先跑个服务」「先注册个账号」的东西，你发出去 10 个人，会有 8 个卡在第一步。

一个 `.html` 文件，双击。**没有第二步。**

| | |
|---|---|
| **单文件产物** | 一个 `.html`，零外部资源。断网可用，无 CDN 依赖 |

## 快速开始

```bash
git clone <this-repo>
cd single-file-exam-engine

# 用自己的题库生成
python3 build.py examples/demo.yaml

# 指定输出名
python3 build.py mybank.json -o 期末复习.html

# 只校验题库，不生成
python3 build.py mybank.yaml --check
```

然后双击生成的 `.html`。

## 题库格式

写 YAML（也支持 JSON，两种解析出来的结构一样）：

```yaml
meta:
  title: 期末复习 · 第一章
  pass_score: 60

questions:
  - type: 单选
    q: 题干写在这里，支持换行和「」等中文标点。
    options:
      - "选项 A"
      - "选项 B"
      - "选项 C"
      - "选项 D"
    answer: B                    # 也可以写 1 / [1]
    explain: |
      解析写在这里。
      多行可以用 | 块。

  - type: 多选
    q: 下列哪些正确？
    options: ["甲", "乙", "丙", "丁"]
    answer: [A, B]               # 也可写 [0, 1]

  - type: 判断
    q: 这句话是对的。
    answer: 错                    # 对/错、true/false、√/× 都认
    explain: 为什么错。

  - type: 填空
    q: 计算结果为 ____。
    accept: ["42", "42.0"]        # 多个可接受答案
    case_sensitive: false         # 默认忽略大小写

  - type: 简答
    q: 简述两者的区别。
    keywords: ["关键点一", "关键点二", "关键点三"]
    reference: |
      参考答案。命中一半以上关键词判为正确。
```

### 题型别名

`type` 字段中文英文都认，不想记就用最顺手的那个：

| 规范值 | 可用别名 |
|---|---|
| `single` | 单选、radio、choice |
| `multiple` | 多选、multi、checkbox |
| `judge` | 判断、bool、truefalse |
| `fill` | 填空、blank |
| `short` | 简答、essay、subjective |

### 答案是这么写的

| 题型 | 写法 |
|---|---|
| 单选 | `answer: B` / `answer: 2` / `answer: [1]` |
| 多选 | `answer: [A, C]` / `answer: [0, 2]` |
| 判断 | `answer: 对` / `answer: false` / `answer: √` |
| 填空 | `accept: ["答案1", "答案2"]` |
| 简答 | `keywords: [...]` + `reference: ...` |

## 判分规则

| 题型 | 规则 |
|---|---|
| 单选 / 多选 | 选项集合完全一致才算对（多选少选都不给分） |
| 判断 | 精确匹配 |
| 填空 | 忽略空格、全半角标点、大小写；带 `%` 的按数值比较（`20` 与 `20%` 视作相同） |
| 简答 | 关键词命中率达到 50% 判对；没有 `keywords` 则标记为「需自评」，不参与自动计分 |

每题默认 1 分，可在题目里用 `score:` 单独指定。

## 验证

本仓库的判分逻辑经过真实浏览器（Playwright + Chrome）端到端验证：

```bash
python3 -m pip install playwright
python3 test_grade.py
```

测试流程：打开生成的 HTML → 逐题模拟点击/填写 → 交卷 → 断言每题判定结果与预期一致。

```

  Q1  判定=ok  期望=ok   ✓ 正确
  Q2  判定=ok  期望=ok   ✓ 正确
  Q3  判定=ok  期望=ok   ✓ 正确
  Q4  判定=ok  期望=ok   ✓ 正确
  Q5  判定=ok  期望=ok   ✓ 正确
  Q6  判定=no  期望=no   ✕ 错误      ← 故意答错，验证能正确识别
  Q7  判定=ok  期望=ok   ✓ 正确
  Q8  判定=no  期望=no   ✕ 错误      ← 故意答错
```

另一支校验脚本 `verify.py` 检查产物完整性：数据块可解析、占位符已替换、**无任何外部资源引用**。

## 它能做什么，不能做什么

**能做：** 个人自测、小班教学、企业培训测验、任何「有一批题想让人能练」的场景。

**不做：**
- **不管考试安全**——答案就写在 HTML 源码里，懂技术的用户按 F12 就能看到。这是刻意的取舍：单文件、离线的代价就是无法防作弊。需要防作弊请用带后端的方案。
- **不做成绩汇总**——没有服务端，交卷结果只在页面里，刷新即失。
- **不做题库编辑界面**——题在文本文件里改，这是故意的，纯文本能进 git、能 diff、能被脚本处理。
